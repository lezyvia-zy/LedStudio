> **覆盖 = 连环扫 + 两种铺法 + 覆盖等级（2026-10-24，用户「这个效果现在的状态是等于只有一半……应该接着第一种再去覆盖第二种这种方式」+「它有两种覆盖效果，一种是渐变色，一种是纯色」+「我希望可以调整覆盖的等级，也就是有多少颗灯参与覆盖。速度也可调」）**：旧实现每个周期把覆盖头从 0 推到 `len`，然后**整条跳回底色** —— 只有「第 1 色 → 第 2 色」半程，而且周期末拍只到 `len-1`（最后一颗永远盖不到）。现在 `coverTint()` 是**无状态公式**：第 `r` 趟（`r = ⌊tick / period⌋`）在 `r·period + ⌊pos·period/S⌋` 拍扫到第 `pos` 颗，`r` 为奇数时方向反过来（左右交替），颜色在主 / 副色之间交替（**同日第三轮起改成按调色板轮换**，见段末）—— 任何一帧都能直接从 `gen_tick` 推出来，导出的 C 是同一套循环（`test_effects_c_exec` 逐字节比）。**`cover_span` = 覆盖灯数（等级）**：一趟最多扫过多少颗（0 / 超过分区长度 = 整条），其余灯一直是底色 —— 40 颗的顶环填 16，就只有前 16 颗在动。**`cover_mode` = 0 纯色 / 1 渐变**：纯色扫到就是整块颜色（硬边）；渐变按位置铺 `i·256/(S-1)`，第 2 趟是 `255-g`（一趟一换面），正是固件 `PixelColorCover()` 里 `GradTbl` 那种铺法。`period` 在覆盖里是「**速度(拍/趟)**」（越小越快；往返两趟 = 一个来回），界面那一格的标题跟着配色换（`#fPeriodLab`）。`hue[]` 在覆盖模式下改当 **0..255 的 tint**（0 = 主色 / 255 = 副色 / 中间 `>>8` 插值，`wipeColorAt()`），**`0xFE` = 副色那个哨兵已废**；导出结构体**不加列** —— 覆盖借用 `E->width`（灯数）/ `E->gap`（方式）。**`cover_dir` = 0 往返 / 1 单向**（同日第二轮加的，用户「覆盖的方向需要可调，现在是来回覆盖，还有一种是单向覆盖」）：单向 = 每趟都从同一头推过去，颜色仍一趟一换（像跑马灯从头刷），`pos` 不再按 `r` 奇偶翻转。**混合**（`cover_mode = 2` + `cover_group` = 每组几趟，1..16，用户「纯色和渐变能不能混合在一起？比如前几组是纯色，后几组就变成渐变色」）：每 `group` 趟换一次铺法、从纯色开始（`⌊ri/group⌋` 奇数 = 渐变），铺法按 **`ri`（最后一次扫到它的那趟）** 而不是当前趟 `r0` 算 —— 换招那一帧同屏就是「上一趟扫到的纯色段 + 这一趟扫到的渐变段」，所以一个模式里两种铺法都看得到。导出继续借字段：`E->hue_base` = 方向、`E->hue_speed` = 每组趟数（`gap` = 铺法 0/1/2），结构体仍不加列。老存档零迁移（四个字段缺省 = 整条 + 纯色 + 往返 + 每组 1 趟）。**多色轮换（同日第三轮，用户「调色板需要多种颜色。参考其他几个色彩模式，最多16种」）**：颜色不再固定 `pal[0]` / `pal[1]` —— 第 `r` 趟用 `pal[r % n]` 当底、`pal[(r+1) % n]` 盖上去（`n` = 调色板颜色数，`colorUpdate()` 的覆盖分支每拍按 `⌊gen_tick / period⌋ % n` 取，导出的 `led_gen_tick()` 里同构，走 `led_gen_palette[E->pal_first + ...]`），所以**每一趟的盖色正好是下一趟的底色** —— 换趟那一帧不跳色；`n = 2` 时与老版逐帧一致（±0，同一对颜色、同样的 tint）。`hue[]` 的 tint 相应改成**相对本趟颜色对**（`ri == r0` ? 盖色 : 底色；渐变是 `g` / `255-g`），`wipeColorAt()` 与 C 里那段插值一个字没改。调色板上限 16（`palFixed(WIPE)` 由 2 改成 0 = 自由增删，覆盖至少留 2 个）。
> **覆盖的铺法改由调色板条目自带（2026-10-24，承接上一条；用户「先按你说的做，我看看结果」）**：`cover_mode` / `cover_group` 退休 —— 调色板条目有两种形态：**纯色 `[r,g,b]`** 与**两端渐变 `[r,g,b,r,g,b]`**（`palIsGrad()` / `effPaletteRaw()`；`effPalette()` 仍只取首端三色，跳变 / 呼吸 / 彩虹 / 列表色块 / 导出 `c1 c2` 零变化）。**`hue[]` 在覆盖下改成「条目索引」**：`coverEntry()` 写 `hue[i] = (ri < 0) ? 0 : (ri + 1) % n`（0 = 第 0 趟之前的初始底色 / 不参与的灯），取色在 `wipeEntryAt(c, idx, i, S)` —— `c.palette[idx]` 首端 + `c.paletteB[idx]` 末端（`instApplyPreset` 从条目的 6 个数装进来），纯色条目两端相同 = 硬边，渐变条目 `t = min(255, ⌊i·256/(S-1)⌋)` = 位置渐变（端点精确、中间 `>>8`，`S = 1` 给末端色）；`S` 走 `wipeSpan()`，与 `coverEntry` 共用同一条夹紧。于是「一趟硬边、一趟渐变」只需把对应条目加成渐变 —— 不再需要「混合」这个参数。导出表 **每条目两行**（首 / 末；纯色条目重复自己，`pal_first + 2k` / `+1`），STEP / BREATH 的取色改成 `+ 2u * idx`（行为不变）；WIPE 的 `zone_render` 只输出索引，`render_mode` 用 `pa/pb + t` 插值（与 JS 逐字节，`test_effects_c_exec` 11 模式），`E->gap` / `E->hue_speed` 归还（仍借 `width` / `hue_base`，**结构体一列没加**）。老存档一次性迁移（`cover_mode` 1 → `[pal[i] → pal[i+1]]` 渐变链、2 → 按 `cover_group` 分组、第 0 组留纯色；迁完置 0，幂等）。界面：删「覆盖方式」「每组趟数」，调色板加「+渐变」（胶囊 = `linear-gradient(90deg,A,B)` + 左右两块透明热区），取色面板底部 `#cpExtra` 在「纯色 ↔ 渐变」间切换 —— **这两样只在「覆盖」出现**（`show('fxPalAddGrad', mode === WIPE)`；`renderPalette` 的 `canGrad` 决定条目画胶囊还是普通色块），跳变 / 呼吸那边 6 数条目按首端色显示、数据不动（用户实测后「怎么跳变和呼吸的调色板也加入了渐变色设置，这两个是不需要的吧」）。**取舍**：渐变按灯位 `i` 铺（不是扫描顺序）→ 往返第 2 趟不翻面；跳变 / 呼吸看到渐变条目只取左端色。

> **呼吸 = 对称包络 + 平滑曲线（2026-10-23 用户「呼吸色效果也同跳变最开始一样会有抖一下的问题…只是渐亮和渐暗时长一样」；2026-10-24 用户「感觉呼吸效果很生硬」）**：旧的 `breathGain()` 是 `0 → 255 → 0` 三角波：每个周期的**起点那一拍正好是 0**（末拍也只有 8/255），而换色恰好也落在这一拍 —— 50Hz 下 20ms 的纯黑闪就是「抖一下」。现在呼吸是**对称包络 + 平滑曲线**：`breathEnv(tick, period, rise)` 渐亮 `rise` 拍、满亮 `period - 2*rise` 拍、渐暗同样 `rise` 拍，最暗那一拍停在 ≈`255/(rise+1)`（不落 0），换色在这一拍；亮度走 `breathCurve(u) = u²(3-2u)/65536`（smoothstep，`u = (t+1)·256/r`，两端导数为 0，纯整数、无查表无浮点）—— 生硬的根子在线性斜坡每拍恒定 `255/r`：暗部等于「亮度翻倍」（30 拍时 8 → 17 → 25）、亮部又几乎不动，看着一格一格跳。参数是呼吸**自己的** `b_rise`（渐亮 = 渐暗）/ `b_hold`（亮），周期 `period = b_rise × 2 + b_hold`（`breathPlan()`，上限 600，超了先压「亮」保住对称）；界面只出现「渐亮=变暗(拍)」+「亮(拍)」两行，「周期(拍)」只读、由 `breathSyncPeriod()` 自动算好。实例里三段仍塞进 `step_rise / step_hold / step_fade`（`fade = rise`），`renderZoneMaskTo` 与导出的 `effShape()` 共用 —— **导出结构体没加字段**，生成代码 `led_gen_breath(tick, period, rise)` 自带 `led_gen_breath_curve()`（同一条 smoothstep；不借 `led_gen_step_env` —— 跳变要直线、呼吸要曲线）。老存档没有 `b_rise` → 摊成 `period/2 + 0`：周期不变、曲线变软（换色那一拍从 0 抬到 ≈255/(r+1)），黑帧没了；出厂 / 新建 / 「多色呼吸」预置是 `b_rise = 40` / `b_hold = 10`（90 拍 = 1.8 秒），20 拍以下才会重新看出台阶。
