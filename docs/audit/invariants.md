## 13. 有意为之，不要「顺手改」（改这些等于改产品语义）

1. **「音乐来了」是手动布尔，不是真 FFT**：它模拟的是固件那条 `ring_set_audio_level()`（帮助页 639–642 已说明）。要接真音频，接口就是 `syncPreviewSpeed` / `speedWhich`。
2. **判档是保守的**：`fast >= slow` 时一律慢档，与打补丁前行为一致（`ringIsFast` 1531 / `led_gen_tick` 的 C 侧表达式）。要"更激进"就是改判据 —— 那必须 C/JS 同步 + 跑真编译。
3. **`ring->speed_slow / speed_fast` 只是判档参考**：各效果用自己配的 `fast/slow`（firmware-contract.md 第三节），不要改回"ring 级覆盖实例级"。
4. **`zones: []` = 覆盖全部分区**（`bindZones`）：新增分区能自动跟上，这是特性；要表达「一个分区都不跑」得用 `b.none = true`（模式页「全不选」），**不能**再用空数组 —— 否则「全取消」会被当成「全部分区」，画面反而全亮。
5. **覆盖参数是完整效果副本**（`resolveEffect`）：改原效果不会影响已覆盖的绑定，`V33` 只提示不合并。
6. **预览与生成的代码必须逐字节一致**：任何渲染/参数改动都要过 `test_effects_c_exec`；为了让预览"更好看"而在 JS 侧加效果是禁止的。
7. **`undo/redo`、`打开工程` 必须原地改写 `state`**（`Object.assign`，坑 1）：不要为了"干净"改成重新赋值。
8. **分区在 SPI 链上连续编号**（`start + i`）：非连续编号需要新映射层（firmware-contract.md 第七节），别在 UI 层硬凑。
9. **只改帧内容的操作必须走 `applyFrame()`**（坑 2）；**`S()` 懒建 sim 必须套用模式**（坑 3）。
10. **每灯颜色源只用 `hue[]` 一个字节编码**（`renderZoneMaskTo` / C 的 `led_gen_hue[]`）：`0xFF` = 效果当前色、`0x00..0xFD` = `spectrum_tbl` 下标（本层空间色相 / 效果级彩虹）；**覆盖模式是唯一例外** —— 它把 `hue[]` 当 0..255 的 tint，且**相对「本趟」的颜色对**（0 = 本趟底色 = 上一趟盖上的色、255 = 本趟盖色、中间按比例插值；渐变时 `ri == r0` 取 `g`、否则 `255-g`），连环覆盖的往返和位置渐变都靠它表达（2026-10-24 起**不再有 `0xFE` = 副色这个哨兵**）。颜色对本身不在 `hue[]` 里：`colorUpdate()` 的覆盖分支按 `⌊gen_tick / period⌋ % n` 从调色板取 `pal[idx]` / `pal[(idx+1) % n]`（`n` = 调色板颜色数，最多 16；2 个颜色 = 老版主 / 副交替）—— **别把它固定成 `pal[0]` / `pal[1]`**，否则第 3 个颜色起永远轮不到；也别让 tint 回到「按 `r` 奇偶」：tint 的 0 / 255 两端是**跟着趟变的**，按绝对趟号算会与颜色对错位。同日第二轮加了 **`cover_dir` = 1 单向**（每趟都从同一头推、颜色照旧一趟一换）与 **`cover_mode = 2` 混合**（`cover_group` 趟换一次铺法，从纯色开始）—— 混合的铺法必须按 **`ri`（最后一次扫到它的那趟）** 分组，不能按当前趟 `r0`：按 `r0` 的话换招那一帧整条会一起硬切，用户要的「上一趟纯色段 + 这一趟渐变段同屏」就没了。覆盖的判断必须排在查表之前；0xFD 以下都可能被彩虹算出来，别再占别的哨兵值。纯色 / 渐变 / 呼吸每帧只算一次颜色，彩虹（q/r 递推，无除法）碰像素；覆盖每像素一次乘加（`wipeColorAt` / C 里那段插值，`>> 8`，**无除法**）；跳变除了换索引还要乘一个亮度包络（`stepEnv` / C 的 `led_gen_step_env`，每分区一次除法 + 每像素一次乘加）—— 除法绝不能挪进像素循环。**跳变不能退回「硬切」，也不能落全黑**：包络最后一拍停在 ≈`255/(fade+1)`（不是 0）—— 灯已经暗到看不见，但留一个全黑帧在 50Hz 下就是一次闪，换色处会「抖一下」。呼吸同理（`breathEnv` / C 的 `led_gen_breath`，坑 30）：它是「渐亮 = 渐暗」的对称包络 + **smoothstep 曲线**（`u = (t+1)·256/r` → `u²(3-2u)/65536`，两端导数为 0）—— **别改回线性**（暗部每拍「亮度翻倍」= 看着一格一格跳，就是 2026-10-24「生硬」那条），也别破坏「第 `r` 拍正好满亮」「渐暗逐拍镜像（末拍 = 首拍）」这两条：接缝上一跳，换色处就又「抖一下」。
11. **编辑台的「暂停帧」是取样，播放必须从 tick 0 起**：`stageSampleFrame()` 只拨暂停预览实例的相位（否则呼吸 = 包络刚起步（≈255/渐亮，很暗）、跳变 / 覆盖 = 第 1 色、渐变 = 红，跟纯色一模一样，看着像「改了配色没生效」）；`stageToggle()` 先落 `stagePlaying` 再 `stageSync()`，样本帧**不能**带进播放、更不能进 C —— 导出与 `test_effects_c_exec` 的逐字节比对仍以 tick 0 为准。编辑台的实例一律按 `editTarget()` 建（微调「覆盖参数」时画覆盖，不是库里 id 相同的原效果），缓存键带 `eff:` / `bind:` 前缀，别退回只看 `e.id`。
