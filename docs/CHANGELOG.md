## 2026-10-28（第九轮）—— 音乐阈值可调（滑杆针 + 「阈」格）+ 「音乐来了」随机注入

**动机**（用户原话）：「1、音乐信号的阈值要可调，现在固定到4了。可以在音量的滑块上增加一个滑针来调整阈值，同时在音量条的末尾处增加一个参数输入框。2、点击【音乐来了】就开始自动输入随机数，模仿板上真实情况。再次点击就取消，默认输入的是0；」

**根因**：① 阈值一直是 `FW.LED_FFT_THRESHOLD(=4)` 这个常量（`speedWhich()` / `ringSpeedFromAudio()` / 界面读数各读一次），用户没法在工具里试「阈值调高以后音控闪/快慢档还跟不跟」；② 「音乐来了」是 `fftDemoLevel(tick)` 的 50 拍固定鼓点（210..245 冲高 → 线性衰减），节奏是算出来的、不像板上真实音乐，而且关掉后还留着上一次的音量。

**改动**：① 阈值进工程 `state.anim.thr`（0..255，出厂 4 = 固件宏，老存档补默认值）；`fftThreshold()` 夹范围；`ringSpeedFromAudio(r, level, thr)` / `simSetAudioLevel(sim, level, thr)` / `speedWhich()` 全部带上它（**第三个参数**，不传 = 4）。② 预览条：音量滑杆上叠一根**可拖的竖针** `#aThrPin`（`cpBindDrag` + `thrAtClientX()`，按滑杆矩形折算、两端扣掉 range 滑块半径），滑杆末尾加**「阈」数字框** `#aThr`；两者写同一个值，手动档下一起灰掉。③ **只影响预览**：导出代码不含这个数（固件读 `led_ring.h` 的宏）—— 写进 invariants §13-1 / 帮助页 / tooltip。④ 「音乐来了」= core 里的 `fftMusicLevel()`：每 20ms 一拍**随机注入**（底噪 0..5 + ≈10% 概率起鼓点 110..255 + 余音每拍衰减 10..29），固定种子 LCG（重放一致、可测）；**再点一下取消 → 音量回 0**；`loop()` 改成「只开音乐也继续跑、但不推进帧」，所以暂停时也在跳。

**测试**：`test_anim2` D/E 段 +8（阈值格 / 针初值 4、改 10 后音量 5 慢 11 快、存盘 `thr`、拖针到中间 ≈128 / 最左 0 / 最右 255、手动档三项一起灰掉、取消后 `fft === 0`）；`test_effects_core` 9b/9c +12（自定义阈值 60 / 阈值 0 的边界 / `fftThreshold` 夹值、随机音源范围、底噪与鼓点都出现、余音连续段、固定种子可重放、换种子变样、默认阈值下快慢两边都看得到）。全量 26 套件 / **1897 项** / 0 FAIL。

**影响**：`docs/audit/anim.md` A7、`docs/audit/invariants.md` §13-1、`CLAUDE.md` 坑 42、`HANDOFF.md` 第九轮、README 第 4 步。老存档没有 `anim.thr` → 4（行为不变）；`fftDemoLevel()` 已删除。

> **同日修正（第十轮）**：① 阈值不再「只影响预览」——用户要求「最后所有的都要以此工具导出的 C 为准」，所以它改成随导出写进 C（`LED_GEN_FFT_THRESHOLD`），判档也搬进生成的 `led_gen_tick()`；② 音量刻度从 0..255 收成 **0..20**。

## 2026-10-28（第十二轮）—— 所有时间参数改成按 ms 显示（内部仍存拍，一律向上取整）

**动机**（用户原话）：「现在的计时都是根据拍子数来的，而且是20ms一拍。我希望将所有可调速的参数都改为根据实际时间来填，单位就还是ms」＋「要是出现无法整除的情况…」「一律向上」。

**根因**：效果卡 / 图层卡上还有一大半时间格子直接暴露「拍」（慢速 8、渐亮 4、周期 90、刷新间隔 4、旋转 3…），用户得自己按 20ms 换算；只有「闪烁」那三格已经改成 ms，于是同一块界面两种单位。

**改动**：① 效果卡：`慢速 / 快速 / 停留 / 渐亮 / 亮 / 变暗 / 周期 / 速度(ms/趟) / 彩虹旋转` 全部显示成 **ms**（`fxMsOf` / `fxTicksOf` / `msBox`），max / min / step 都按拍换算（例如渐亮 0..5100ms、步长 20）；② 图层卡：`脉动周期 / 刷新间隔 / 旋转` 也进 `MS_FIELDS`（闪烁三格原本就是），`MS_TICK_MAX` 区分 uint16 列（65535 拍）与 uint8 列（255 拍）；③ 录入一律 **向上取整** 到整拍（填 30 → 40、填 210 → 220），`onchange` 回显实际生效值（与「闪烁」三格一致）；④ 标签 / 提示 / 帮助页一并改口（「渐亮(ms)」「停留(ms)」「速度(ms/趟)」…），帮助页加一段「所有时间都按 ms 填」的总说明；⑤ **底层数据结构一点没变**（还是拍、导出表也还是拍），所以老工程不用迁移、固件不用重编。

**测试**：`test_fx_presets` 数值断言全部换成 ms（填 120ms → 6 拍、填 30ms → 2 拍并回显 40ms），新增「时间类格子：显示 ms / 内部存拍」四条（慢速 8 拍 = 160ms / 填 30 → 2 拍 / 回显 40 / 图层脉动 60 拍 = 1200ms）；`test_grad` / `test_override` 的输入值与上限换算成 ms。全量 26 套件 / **1923 项** / 0 FAIL。

**影响**：`docs/audit/fx.md` F21、`CLAUDE.md` 坑 43、`HANDOFF.md` 第十二轮、帮助页 / README。界面单位变了但**导出与固件完全不变**；下一轮是「每效果平滑 T（只在慢档）」。

## 2026-10-28（第十一轮）—— 「音乐 → 快慢档」加采样 + 快档阻尼（慢→快立刻、快→慢有惯性）

**动机**（用户原话）：「30ms信号采样是固件里面有其他的计时来确定，可以30ms也可以40ms 这个影响不大。采完以后，直接读取参数当前值就行了。我说的快档450ms间隔，不是指采样间隔，而是更新参数值的时间。进快档不需要消抖。」＋「时间向上取整」＋「平滑…快档的就不用了做平滑了，减少计算量」。

**根因**：第十轮把判档做成了「每拍读一次音量、过阈值就切档」—— 音量在阈值附近抖一下档位就来回收，观感上「慢→快」还行、「快→慢」像急刹；这也和老固件那套「关键帧之间插值」解决的不是同一件事。

**改动**：① 判档改成**采样 + 迟滞**：每 `LED_GEN_AUDIO_SAMPLE_MS`（出厂 **40ms = 2 拍**）采一次音量；采到 > 阈值就**立刻**进快档并至少保持 `LED_GEN_STAGE_HOLD_MS`（**450 → 向上取整 460ms = 23 拍**），到期后仍安静才回慢档 —— 于是「慢→快干脆、快→慢有阻尼」。② 两个数进工程（`state.anim.audioSampleMs / stageHoldMs`）、预览条上可调、**随导出写进 C 的两个宏**；`simSetAudioLevel()` 退化成「只写音量」，档位由 `simAudioStep()`（C：`led_gen_audio_step()`）算，换模式时复位；状态只有 4 个整型量（每引擎一份，不是每灯）。③ 换算一律**向上取整**（`msToTicksUp()`：填 30ms → 40ms、21ms → 40ms；0 仍是「关 / 不保持」）。④ 工具里的「手动慢/快」走 `simSetSpeedLocked()`（`stage_lock`），采样与迟滞不跑；「单步」按即时判断取拍数。⑤ 预览条新增一行「采样 / 阻尼」（40 / 450，读数写实际生效的 `40 / 460 ms`）。

**测试**：`test_effects_core` 9b 重写（采样周期没到不切 / 采到立刻切 / 400ms 内不回 / 520ms 后回 / 阈值与夹值 / 向上取整）；`test_effects_c_exec` 新增「迟滞追踪」：C 侧直接打印引擎内部 `led_gen_stage` 逐拍状态，与 JS `sim.stage` 逐字比对（实测两边都**第 11 拍进、第 34 拍回，差 23 拍 = 460ms**）+ 进/回时机断言；`test_anim2` +4（两个格子的初值 / 取整 / 回显）；`test_effects_c` +1（两个新宏 + `led_gen_audio_step`）。全量 26 套件 / **1918 项** / 0 FAIL。

**影响**：`docs/audit/anim.md` A7（⑤）、`docs/audit/invariants.md` §13-1 / §13-12、`CLAUDE.md` 坑 42（⑦）、`HANDOFF.md` 第十一轮、`docs/firmware-contract.md` §6.2、帮助页 / README。导出头多了两个宏、`led_gen_tick()` 多了采样状态 → **老工程要重导出重编**（结构体没动）。

> **同日修正**：采样周期**不在界面上暴露**（用户：「采样这个时间不需要显示出来，因为这个是在固件里面定好了的。工具就默认 40ms 一次就好了」）—— 预览条只留「阻尼」一格，`LED_GEN_AUDIO_SAMPLE_MS` 仍固定 40 并随导出写进 C。

## 2026-10-28（第十轮）—— 阈值随导出写进 C（引擎自己判档）+ 音量刻度收成 0..20

**动机**（用户原话）：「不行，阈值设定在这里设置好了以后，也要在固件里面应用。最后所有的都要以此工具导出的c为准，导出后就直接合入固件进行编译烧录实板测试了，固件内的，除了条件限制需要认为手动修改的外，都要以此为准。所以不要考虑现在的固件已有的彩灯驱动，只是作为思路参考。还有音量范围不需要那么大，最多也就【0~20】」

**根因**：第九轮把阈值做成了「只影响预览」——生成代码仍靠平台的 `ring_set_audio_level()` 把 `ring->speed_cur` 改好，阈值又读固件 `led_ring.h` 的 `LED_FFT_THRESHOLD`。那是**第二份来源**：工具里调了阈值、导出的 C 却不管，板上按固件的宏走，两边必然对不上（这也违背「导出即真相」这条主线）。

**改动**：① `exportEffectsC()` 写 `#define LED_GEN_AUDIO_MAX 20u` + `#define LED_GEN_FFT_THRESHOLD <A().thr>u`（阈值来自工程 `state.anim.thr`）；② `led_gen_tick()` 改成 `fast = led_gen_hal_audio_level() > LED_GEN_FFT_THRESHOLD && ring->speed_fast < ring->speed_slow` —— **不再读 `ring->speed_cur`**，平台只要实现 HAL 那个音量函数（原型在生成头里也声明了一份，避免与 `led_gen_hal.h` 的入口原型打架）；③ 音量刻度统一 **0..20**（`FW.AUDIO_MAX`）：滑杆 / 阈值格 / `A().fft` / `simSetAudioLevel()` / `fftMusicLevel()` 全按它（随机音源改成底噪 0..1 + 鼓点 8..20 + 余音）；④ 导出面板的补丁说明 [7]、`GEN_COMMENTS.syncspeed / audioif / audioCfg`、HAL 的 `led_gen_hal_audio_level` 文案全部改成新口径；`docs/firmware-contract.md` §6.2 重写。

**测试**：`test_effects_c` +4（两个宏存在且阈值随工程变、tick 用 HAL 音量 + 宏判档、不再读 `ring->speed_cur`）；`test_effects_c_exec` 的 C 侧改成用 `g_audio` 驱动 HAL，并新增一段「阈值下沿」：工程把阈值设成 12、音量给 10（> 老阈值 4）→ 必须仍算安静，与「全程静音」逐字节相同（写死 4 的话这里会亮）；`test_effects_core` / `test_anim2` 的刻度断言换成 0..20。全量 26 套件 / **1903 项** / 0 FAIL。

**影响**：`docs/firmware-contract.md` §2.1 / §6.1 / §6.2 / 附录 B、`docs/audit/invariants.md` §13-1 / §13-12、`docs/audit/anim.md` A7、`CLAUDE.md` 坑 42、`HANDOFF.md` 第十轮、帮助页 / README。**老工程导出后必须重编固件**（头里少了两个宏，且判档路径换了）；固件那边的 `LED_FFT_THRESHOLD` 与 `ring_set_audio_level()` 可以不再动，留着也无害（引擎不读 `ring->speed_cur`）。

## 2026-10-27（第八轮）—— 预置「跳变」= 配色「跳变」：同一个旋钮只有一份

**动机**（用户原话）：「我现在在测试跳变这个动画模板。在色彩配置里面我们已经添加了跳变这个配置，这两者应该是一回事。选择动画跳变，即颜色也默认切换为跳变，同时调参接口也都是用同一套。你觉得呢？」

**根因**：和「呼吸」（F18 / 坑 40）**一模一样的病** —— 预置「跳变(渐暗后跳回)」是 `color:1 渐变 + 填充层锯齿脉动（wave:2 / pulse_period:30 / pulse_amp:255）`，亮度包络活在**图层**上；色彩配置的「跳变」是 `FW.COLOR.STEP + rise/hold/fade + 调色板`。套完预置，配色下拉还停在「渐变」、节奏也不在「渐亮 / 亮 / 变暗」那三行里 —— 同一件事两套旋钮。

**改动**：① 预置「跳变(渐暗后跳回)」→ `color:3`（跳变）+ `rise:0 / hold:0 / fade:30`（停留 30 拍 = 600 ms：硬启亮、匀速暗到 ≈9/255，**故意不落全黑**）+ **3 色调色板**（红 / 绿 / 蓝）+ 一个满亮填充层（`pulse_period 0`）；实测逐拍 `247 → 9` 后跳回 247 并换下一色，与旧锯齿（`255 → 0`）观感一致；② 套完配色下拉自己变成「跳变」，旋钮就在「色彩配置」的「停留 / 渐亮 / 亮 / 变暗 + 调色板」那一排，和手动选「跳变」完全同一份数据（想单色把调色板删到 1 个，想柔和用「七彩跳变」的 6 色 + 4/8/8）；③ 帮助页：② 填充表（三角脉动只剩「呼吸彩虹」在用）、「颜色从哪来」、「配色表 → 跳变」那段、**「常见做法」新增「跳变（几种颜色轮着亮）」一行**。

**测试**：`test_fx_presets` +4（套完 `color=3` / 3 色 / 0-0-30 → 停留 30、图层不再有锯齿脉动、配色下拉与四个数值框自己切过去且一致、调色板 3 个色块）。全量 26 套件 / **1877 项** / 0 FAIL。

**影响**：`docs/audit/fx.md` F20、`CLAUDE.md` 坑 40（补 ④）、`HANDOFF.md` 第八轮结论。老工程里已经套过的「跳变」保持原样（存的是 `color:1 + wave:2`，不迁移），要新行为重新套一次预置；「七彩跳变」本来就是配色跳变，未改。

## 2026-10-27（第七轮）—— 「最高亮度」全局统一 + 三列时间加宽成 uint16（上限 21.8 分钟）

**动机**（用户原话）：「你提到的这两点都改掉」—— 指的是第六轮收尾挂出来的两条待决：① 「填充亮度」只在音控闪层上叫「最高亮度」，别的填充层还叫填充亮度；② 三列时间的上限仍是 255 拍 = 5100 ms，填不了「几分钟闪一次」。

**根因**：① 第六轮把改名做成了「闪层专用的三元特判」（`renderLayers()` 里 `flash && key === 'level'`），同一格旋钮在不同图层上两个名字；② `pulse_period` / `flash_fast` / `flash_on` 在 C 结构体里是 uint8，而 `pulse_period` 还被三角 / 方波 / 锯齿当脉动周期共用 —— 想加宽就得同时动结构体、`led_gen_pulse()` 的形参和 `flash_age`。

**改动**：① 改名全局化：`LAYER_FIELDS.fill` 的 `level` 标签、帮助页 ② 填充表、校验 V25 文案、`GEN_COMMENTS.llevel`（中 / 英）全改「最高亮度（整环最亮时有多亮）」，`renderLayers()` 那个特判删掉；「最低亮度」只留给带 `flash_low` 的音控闪层；② 三列时间 `uint8_t` → `uint16_t`（`led_gen_layer_t` 仍是 21 列，前面的列一列没挪），`led_gen_pulse()` 的 `period` 形参、`led_gen_flash_gain()` 的 `t` / `on`、`led_gen_inst_t.flash_age` 一起加宽（只加宽结构体的话调用处会被静默截成 8 位，400 拍变 144）；③ 上限 `FLASH_MS_MAX = FRAME16_MAX(65535) × TICK_MS(20) = 1310700 ms ≈ 21.8 分钟`，`layerNums()` 用 `frame16()` 把存档怪值夹到 0..65535，`onchange` 回显实际毫秒数的行为不变；④ C 侧 tick 里 `fr / ff / fo / per / br` 同步 uint16。

**测试**：`test_effects_core` +3（1000 拍间隔在 2100 拍里真闪 3 次 / `flashPlanOf` 不被夹成 8 位 / `frame16()` 夹值）、`test_effects_c` 断 `uint16_t pulse_period` + 两列时间类型、`test_fx_presets` 上限 5100 → 1310700 并新增「填 600000 ms → 30000 拍」、`test_effects_c_exec` 新增「长间隔闪」（间隔 400 拍跑 405 拍，收在亮段，C ↔ JS 逐字节 + 语义）。全量 26 套件 / **1873 项** / 0 FAIL。

**影响**：`docs/audit/fx.md` F19（四刷）、`CLAUDE.md` 坑 41（补 ⑧）、`HANDOFF.md` 第七轮结论。老存档 0..255 的值一个都没变；`led_gen_layer_t` 变大（18 个 uint8 + 3 个 uint16 + 1 字节对齐填充 = 26），**固件那边要重新导出 + 重编**，别拿旧的头文件混着用。

## 2026-10-27（第六轮）—— 「闪烁」五个旋钮改名 / 改单位：最低亮度填亮度本身，时间按 ms 填

**动机**（用户原话）：「闪烁的这5个可调参数是没问题的。只是名称和描述有点问题。填充亮度改为最高亮度，闪完暗到改为最低亮度，而且数值和亮度应该是对应起来的，不能说是255代表最暗，不符合直觉。间隔时间单位也要改为ms，这样用户在填入时可以直接根据实际时间要求填入对应的参数，而不是数拍子，也包括亮的时间。」

**根因**：① 第五轮把「闪完暗到」挂在 `pulse_amp`（**衰减量**，灭的时候 = `255 - pulse_amp`）上 —— 255 反而最暗，与「数值越大越亮」的直觉相反；② 三个时间直接暴露「拍」（250 / 25 / 10），用户得自己按 20 ms 一拍换算。

## 2026-10-27（第三轮）—— 两套「呼吸」合一 / 调色板里的纯黑占位 / 黑色色块改不动

## 2026-10-27（第二轮）—— 「走到头折返」其实只走到一半就掉头

**动机**（用户原话）：「走到头折返的功能，还是有问题，实际看并没有走到头。走到了一半就掉头了。」

**根因**：上一轮把折叠区间从 `rd`（整环）改成 `half`（半圈）—— 环上没有「头」，我拿「环的对侧」当了折返点，光点只在前半圈来回。更深一层：**环是闭合的**，`genRender()` 又把 `pos` 绕回 `[0, rd)`，「走了几圈」这个信息在渲染层根本拿不到，所以折返点只能落在**接缝**（走到最后一颗灯、绕满一整圈），而圈数必须由推进逻辑数出来。

## 2026-10-27 —— 图层「方向 / 往返」两个参数其实没接上（往返恒等、方向只翻拖尾的边）

**动机**（用户原话）：「往返和方向这两个参数似乎没起作用。」

**根因**：① **往返是彻底的空转** —— `genSpot()` 里写的是 `p0 = L.bounce ? bouncePos(pos, rd) : pos`，而 `genRender()` 早就把 `pos` 绕回 `[0, rd)`；`bouncePos(p, span)` 只在 `p` 超过 `span` 时才折（`two = 2·span`，`t = p % two = p < rd = span`），所以在合法区间里**恒等返回原值** —— 勾不勾一模一样（实测「摆动(往返)」与「单点追逐」逐字节相同，根本没在摆）。C 模板 `led_gen_spot()` 是同一行，固件也一样。② **方向只用来翻拖尾的边** —— `dir` 只进 `FALL.TAIL` 那一支（`dd = dir > 0 ? d : -d`），余弦 / 线性 / 硬边三种曲线下 `|d|` 与 `-d` 完全对称，勾哪个都逐字节相同；而它自己的提示写的是「沿灯号增大的方向跑，还是反着跑」，语义本来就是**走的方向**。顺带发现拖尾的边反了（尾甩在**前面**，彗星看着像倒着飞）。

**改动**：`genSpot()`（core，2733–2755 一带）：`q = L.bounce ? bouncePos(pos, half) : pos`（**折返点 = 环的对侧**，即半圈）+ `p0 = dir > 0 ? q : rd - q`（**反向 = 位置镜像**，整条朝着相反方向走）+ 拖尾 `dd = dir > 0 ? -d : d`（**尾永远拖在身后**）。C 模板 `led_gen_spot()` 逐行对齐（新增 `q` 一行、`p0` 改成三目、`@reverse@` 注释进 `GEN_COMMENTS`），**导出结构体一列没加、固件接口零改动**。界面两行提示与帮助页①光点表把「走到头折返」写清成「跑到环的对侧（半圈）就掉头，配合「起始位」可把来回的那一段挪到任意位置」。

**测试**：`test_effects_core` 新增 5 项 —— 3b 往返（`pos` 与「整环 − pos」逐字节相同 = 真的折返 / 与绕圈确实不同 / 亮点始终不出前半圈）、4b 方向（反向在 `pos` == 正方向在「整环 − pos」/ 与正方向确实不同）、拖尾那条改断「尾在身后」。全量 26 套件 / **1800 项** / 0 FAIL（`test_effects_c_exec` 的真编译逐字节比对同时守着 JS ↔ C 没分家）。

**影响**：`docs/audit/fx.md` F17、`CLAUDE.md` 坑 39。老存档 `direction=0` 的效果现在真的反着走（以前看不出区别）；`bounce=1` 的效果（「摆动(往返)」预置）从「等于单向绕圈」变成真的来回摆。

## 2026-10-24 —— 覆盖改成「连环扫 + 覆盖等级 + 纯色/渐变/混合 + 往返/单向」

## 2026-10-23 —— 跳变的渐亮 / 亮 / 暗时长可调：「渐亮(拍)」+「亮(拍)」+「变暗(拍)」，变暗不落全黑帧

**动机**（用户原话）：「这个跳变配色看起来有点怪怪的，感觉亮的时候就是一瞬间，大部分时间都是在变暗。增加两个设置变量吧，一个是亮的时长，一个是变暗速度。」随后又问「点亮是直接从 0 到 255，还是有个缓慢变亮的过程？」—— 想把点亮也做成可调；做完再问「在切换颜色时为啥会有抖一下的感觉」。

**根因**：`stepEnv` 把停留切成「前 1/8 快速点亮 + 其余全程渐灭」—— 亮段最长只有 1/8 停留；上一版把亮段改成满亮之后，启亮仍是 0 → 255 一拍照跳（20ms 一拍），没有渐变可调。**「抖一下」**（用户补一句：「渐变色里面，从一种颜色变暗切换到下一颜色时，会出现抖一下」）= 两处叠加：① 渐亮第 0 拍恒为 0，接在上一色「变暗」最后一拍（也是 0）后面，换色处**连黑 2 拍**（40ms），4 拍渐亮里能看到的只有 3 级（85 / 170 / 255）；② 变暗最后一拍落到 **0** —— 20ms 全黑一帧在 50Hz 下就是一次闪，紧跟着又跳回 63/127，看着就是换色处一顿一抖。

**改动**：包络换成四段 —— `r` 拍 `255/r → 255` 匀速渐亮（「渐亮(拍)」，`r = 0` 即硬启亮、逐拍与上一版相同；第 1 拍不是 0 —— 换色处不许有全黑帧，否则会连黑两拍、看着发顿）→ 满亮 `h` 拍（「亮(拍)」）→ `f` 拍匀速暗下去、最后一拍停在 ≈`255/(f+1)`（「变暗(拍)」，**不落 0**：全黑一帧在 50Hz 下就是一次闪，换色处会「抖一下」）→ 就在这一拍换下一种；`r + h + f` 之外不再留黑拍：**「停留(拍)」= 渐亮 + 亮 + 变暗，填这三行时自动算好填回那一格**（`stepSpeedOf`，那一格只读；上限 255 拍，超了状态栏说明实际按 渐亮 / 亮 / 暗 多少播）。`stepClamp(d, r, h, f)` / `stepEnv(t, d, r, h, f)` / `led_gen_step_env()` 逐值相同；效果多三个字段 `rise` / `hold` / `fade`（导出的 `led_gen_effect_t` 末尾是 `step_rise` / `step_hold` / `step_fade` 三列，`rowFromEffect` / `CORE.effectPreset` / `instApplyPreset` 全程带着走，实例周期也按三段之和定）。缺省：`rise` = 0（老存档 / 老预置打开即得，逐拍不变）、`hold` = 停留一半、`fade` = 停留 − 渐亮 − 亮。UI 在「停留(拍)」下多三行（只在跳变时出现）；「七彩跳变」预置改成 渐亮 4 / 亮 8 / 暗 8（老效果照旧读自己存的三段）；暂停样本帧停在包络顶点（有亮段停满亮第 0 拍，只有渐亮时停在爬满那一拍）。渲染端仍保留「`r + h + f` 比停留短 → 多出来的拍黑着」的夹紧兜底（老存档 / 手改 JSON）。

**测试**：`test_effects_core` 111 → 122（渐亮形状 `63/127/191/255` + 变暗不落 0 / 换色处没有黑帧 / 顶点 / 一拍照跳 / 夹紧 / 缺省 / 停留 = 渐亮 + 亮 + 暗 / 实例与渲染）、`test_effects_c_exec` 新增一条「渐亮跳变」模式随整帧真编译比对（第 1/6 拍 = 169/254，渐亮分支确实执行；变暗分支也在 37 帧逐字节比对里）、`test_fx_presets` 77 → 80（三行显隐 / 三段之和自动填 / 封顶状态栏 / 切回跳变仍等于三段之和 / 七彩跳变 rise 0 / 暂停样本帧停在爬满那一拍）；全量 **24 套件 / 1440 项 / 0 FAIL**。

## 2026-10-15 —— 批 7-D-4：用户第四轮实测（点灯有偏差 / 形状手柄拖不动）—— 画布映射 + 「谁抢按下」的规则

- **动机**（用户实测两条）：「现在不单单是新建的形状没办法通过鼠标调节大小，**连点选某一个灯都有点偏差了**」。这两条看着无关，其实是同一个根：**屏幕上看到的东西**与**命中测试算出来的世界坐标**用的不是同一套映射，而「这一下算谁的」也没有明文规则。
- **① 根因：画布位图与「CSS 盒子 × dpr」会脱节**（真正的系统性偏移）。浏览器是把 `cv.width/height`（**位图**）**拉伸**到 CSS 盒子上显示的，而命中测试（`s2w`）按 **CSS px** 算 —— 位图一旦过期，整块画布就**按比例偏**、越靠边偏得越多（`test_canvas_map` 实测 CSS 盒子 1200→960 时偏 **212 世界 px**，远超一颗灯的命中半径）。而画布是 flex 子元素：右栏宽度、面板内容高低、滚动条有无、窗口在不同 DPI 的显示器之间移动、浏览器缩放导致 dpr 变化……**都不发 `window.resize`**，原来只挂了 `resize` 与右栏拖拽。现在三道保险：`render()` 开头 `if (canvasStale()) resizeCanvas()`（**任何一次重画都自愈**）、boot 时 `initCanvasWatch()` 给画布挂 `ResizeObserver`、`watchDpr()` 按当前 dpr 登记 `matchMedia('(resolution: Xdppx)')`、dpr 变了重算并**重新登记**。顺带 `resizeCanvas()` 在盒子还没布局出来（宽/高 < 1）时不再把位图设成 1×1。
- **② 命中半径改成「屏幕感知」**：`hitTol() = max(0.42 格, 9 屏幕 px)`（按当前缩放换算成世界 px）。老写法固定 0.42 格（世界 px），缩到 0.3 倍只剩 2~3 屏幕 px —— 等于要求用户按亚像素精度点灯；命中取的仍是**最近的一颗**（不是第一颗），所以放宽不会把点击判给旁边的灯。
- **③ 「谁抢按下」写成了明文规则**（同一个歧义的两个方向，正是用户抱怨的两条）：
  - **手柄任何模式抓住都算改大小**：新增 `handleAnyAt()`（当前形状优先）+ `beginShapeDrag()` —— 一次按住就直接开拖（先 `enterShapeEdit()` 再立刻开 `resize` draft），不再「先点中形状、松手、再按第二遍」。以前**选择模式按在手柄上只是进编辑态**，手感就是「拖不动」。

  - **点灯不再被偷**：双击**落在灯点上**不再进形状编辑态（`dblclick` 里 `if (hit(wx, wy)) return;`）—— 原来连点两颗灯会悄悄把工具换成形状编辑态，之后每次点灯都在挪形状，看着就是「点灯有偏差」。进编辑态的明确入口三条：面板「形状」下拉、新增的「**编辑**」按钮 `#shEdit`、画布上双击形状里的**空白处**。
