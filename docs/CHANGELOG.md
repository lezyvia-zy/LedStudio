## 2026-10-14 —— 批 7-C：画图式铺灯（形状选择框 + 画布拖拽 + 点两下点头尾）

- **动机**：用户实测后的原话 —— 「感觉操作还是有点别扭……在形状选择中做一个截图类似的选择框，让用户来选择将要添加的形状，选择好后，在画布上用鼠标通过拖拽的方式来勾勒出形状，在勾勒形状的过程中，彩灯也随着形状的边框，依次排开，就遵循等间距的要求，如果排不开就让此时的灯做重叠……编辑好形状之后，再让客户定义起始点和方向。预制的形状暂时只需要【直线、圆环、圆角矩形】这三种」。
- **形状选择框**：面板加 `#shGallery`（三格 SVG 缩略图：直线 / 圆环 / 圆角矩形）。**编辑态点它 = 把当前形状立即换成这种（外框不动）**；select / 添加态点它 = 选类型进「画形状」添加态（`shapeTool` + `shAdding`）。高亮永远跟着 `shapeTool`（`syncShapeTool` 不再自动改它）。换类型（外框不动）同样走面板「形状类型」下拉（`shSetKind` / `SHAPE.fromBox`）；**已铺的形状换类型后灯立即跟着重铺**（`shRelay`，不用再拖一下）。
- **画布拖拽**：拖空白 = 新建；拖形状内部 = 挪动；拖四角/四边手柄 = 改大小（`shDown`/`shDragMove`/`shDrop`/`shHover` + `SHAPE.boxOf`/`arcNear`/`fromBox`）。拖的过程中灯沿边框**等间距**实时排开 —— **不带编号**，只在旁边报「N 颗 · 灯距 x px」，排不开就红字「会重叠」，客户拖大拖小直到 ≥ 一格（`shDraftShape` + `render()` 里的预览层）。
- **点两下点头尾**：点「在画布上定头尾」进入点头尾子态（`shPickStep=1`，点空白取消）—— 点形状（投影到最近轮廓）第一下是「头」→ `entry` = 该点弧长，第二下是「尾」→ 按沿路径短边走定 `dir`（`cw/ccw`），两点齐了自动铺编号（`shPickStep1/2`）。`sh.laid` 标记「这形状是不是板上已铺的灯」：拖出来的新形状 `laid=false`（只预览），铺过之后（或 `fromRect`/`fromLeds` 反推出来的）`laid=true`，再拖就**跟着重铺**（`shRelay`）。
- **画完释放 + 点选编辑**（用户第二轮反馈）：拖完形状自动**释放鼠标回到「选择/编辑」模式**，不再停留在「画形状」；**点形状（轮廓或内部，无论已铺与否）就进「画形状」编辑态**（`hitShapeAny` + `enterShapeEdit`，形状优先于选灯 —— 想微调单个灯用框选或「擦除/放置」），编辑态**点空白释放**、**点其它形状随时切换选中**、**Esc 键释放**（`shDown` 里的 `shAdding` 区分「添加/编辑」）。面板不再显示**左上格 / 宽高 / 圆角px / 起点偏移 / 分布 / 圆芯半径张角 / 顶点px / 闭环**，只留**分区 / 类型 / 起始编号 / 颗数 / 方向**（几何靠画布拖、头尾靠点两下）；头/尾标签移到灯点侧边、形状外侧；**手柄画在所有灯之上**（不被灯点盖住，8 个都清楚可见）。改分区「灯数」时，已铺形状**自动同步颗数并增删灯**（`resyncZoneCount`：只删旧号段、再铺新颗数，不碰别的分区；号段超出板内就不动灯、交给 V9）。
- **引擎**：`SHAPE` 新增 `roundPts`（圆角矩形）/ `boxOf` / `fromBox` / `arcNear`；类型 `rect/rrect/circle/poly/line`（`circle` 支持 `ry` → 拖成椭圆），`normalizeShapes()` 同步。
- **测试**：`test_shape` 41 → 55（圆角矩形周长/包围盒、直线开环、椭圆 rx/ry、换类型外框不动、轮廓最近点）；`test_ui` 74 → 107（形状选择框三格 + 拖拽建形状 + 画完释放回选择模式 + 点形状（含已铺形状内部）进编辑/点空白释放 + 编辑态点形状选择框换类型/高亮同步/灯立即重铺 + 面板只留分区/类型/起始编号/颗数/方向 + 点其它形状切换选中/Esc 释放 + 点「定头尾」两下自动铺 + 换类型 + 拖手柄改大小 + 改分区灯数自动增删灯）。全量 **22 套件 / 832 项 / 0 FAIL**。**导出物与契约零改动**。

## 2026-10-14 —— 批 7-A/B：铺灯改成「形状」引擎 + 形状面板

- **动机**：用户实测后的原话 —— 「铺灯这方面似乎还是不够灵活。举个例子，分区1有21颗灯，排布需要类矩形排布，但是现在的工具里面，就没办法编辑出一个闭环的矩形出来……可不可以参考 Windows 画图工具里面的形状功能，先来画出大致的形状，然后再在此形状上编写头尾和顺逆时针方向灯参数」。
- **先钉事实（实测）**：① `GEN.rectPath` 的周长 `P = 2W+2H-4` **恒为偶数**，21 颗永远铺不满一圈（实测 6×7 上必留 80px 豁口）；② 旧的「四边形」那条路其实**能**做 21 颗闭环（弧长真均匀，49.52px），但它的几何参数藏在「矩形环绕圈」那栏里、四边分布由算法定（5/5/5/6）、四角只有一角落灯；③ 同一个 `W` 在两个生成器里含义还差一格（200px vs 240px）。
- **关键认识**：**坐标从来没被导出过** —— 导出物只有 `g_default_zones[] = {start,count,reverse}` 与退路用的 `led_map[]`，所以形状怎么灵活都不碰契约（新坑 20）。
- **core 新增 `SHAPE` 引擎**（`plan` / `info` / `arcs` / `at` / `segs` / `arcAt` / `asCells` / `cellsPts` / `sidesOf` / `count` / `rectPts` / `newRect` / `fromRect` / `fromLeds`；已加进 `CORE`）：
  - **四档分布**：`sides` 每边颗数（`6,5,6,4`，最贴实物灯带）/ `even` 等分弧长（任意颗数与形状）/ `pitch` 等灯距（闭环时报「差多少才回得到起点」）/ `cells` 格点（**与旧 `GEN.rectLeds` 逐字节相同**，老工程原样重现）。
  - **顶点是 px 且允许半格** —— 这正是「21 颗 × 灯距 40px 正好闭环」能成立的钥匙：宽 6 × 高 6.5 的矩形周长 840px，按 40px 正好 21 颗、连缝都等距。
  - **灯距一律按沿路径弧长算**（`arcAt`），不用弦长（拐角弦长必然更短）。
  - 头（`first`）/ 尾 / 方向（`dir`，`ccw` = 编号倒着走）/ 闭环 / 起点偏移（`entry`）/ 角上落灯（`corner`）都是形状参数；`info()` 出一行中文诊断（周长 / 实铺颗数 / 沿路径灯距 / 每边落点 / 闭环残差 / 格点识别 / 与分区号段的对照）。
- **面板**：「分区」页的三套铺灯控件（`#gX0…` / `#cX…` / `#qDir…`）与它们的一次性生成器 `genParams()` / `genInfo()` **整体删除**，换成「铺灯 · 形状」：`#shList`（形状下拉）/ `#shZone`（归属分区）/ `#shKind`（矩形 / 圆 / 多边形）/ 几何（左上格宽高、圆芯半径张角、顶点表）/ `#shDist` + `#shSides` + `#shPitch` + `#shCorner` / `#shFirst` + `#shCount` + `#shDir` + `#shClosed` + `#shEntry` / `#shInfo` 诊断行 / `#shApply`（铺到灯位）/ `#shFlip`（**反向编号**：几何不动只倒编号）/ `#shKeep`（只画不铺）/ `#shAdd` + `#shDel` / `#shFromZone`（**由分区反推**：按现有灯位包围盒生成形状，整数格上能重现旧排布时自动用格点档）。
- **持久化**：`state.shapes[]` 随项目存 / 读 / 撤销；`emptyProject()` 带 `shapes: []`，预设 `PRESET_SP3122D` 的 `zone.rect` 顺带升级成 5 个可编辑形状（预设的灯位仍由 `GEN.rectLeds` 生成，**不点「铺到灯位」对灯位零影响**）；`normalizeShapes()` 给老存档补 `[]`、就地纠正坏字段、分区没了就把 `zone` 置空。
- **画布**：形状画成虚线条 + **「头 N」实心点 / 「尾 M」空心圈**（`render()` 里的参考层，未关联分区用主题强调色）。
- **帮助页**：新增第 4 节「按形状铺灯（矩形 / 圆 / 多边形）」（四档分布表 / 头尾方向 / 四个按钮 / 21 颗闭环的例子），「常见做法」加两行（21 颗闭环、接手老工程）。
- **测试**：新增 `test_shape`(41) —— 逐字节兼容、21 颗闭环、每边 6/5/6/4、反向编号、圆与圆弧、起点偏移、退化形状、由灯位反推、与校验/导出的联动；`test_ui` 72 → 74（旧控件已移除 + `#shInfo` + `SHAPE.plan`）；`test_persist` 31 → 41（形状存盘 / 重开还在 / 切类型不清零几何 / 老存档没有 `shapes` 字段也能打开）。全量 **22 套件 / 785 项 / 0 FAIL**。

## 2026-10-10 —— 速度档跟着音乐变（不需要新的固件补丁）

- **根因**：补丁 [5] 把 `ring_tick()` 换成 `led_gen_tick(ring)` 之后，推进实例的只剩生成代码，而它只读实例自己的 `speed_cur` —— 固件 `ring_set_audio_level()` 每 20ms 写的 `ring->speed_cur` 没人读，速度永远停在慢档。
- **改法（零固件改动）**：`led_gen_tick()` 每帧先算一次 ring 级档位（`ring->speed_fast < ring->speed_slow && ring->speed_cur <= ring->speed_fast`），再把 `I->speed_cur` 设成该实例自己的 `speed_fast` / `speed_slow`。判据保守：固件没接音量或参数退化（`fast >= slow`）时一律慢档，与打补丁前行为一致。
- **预览同源**：`simInit()` 增加 ring 级 `speed_slow/speed_fast/speed_cur`；`simSetSpeed(sim,'fast'|'slow')` 改为「改 ring 级 + 广播」（等价 `ring_set_audio_level()`）；`simTick()` 每拍同步一次。新增纯函数 `ringIsFast()` / `instSpeedFromRing()` / `simSyncSpeed()`（已加进 `CORE`）。
- **界面**：动画页「速度档」新增「自动（跟着音乐）」；新增「音乐来了」按钮（仅自动档可用，文案与 `on` 状态跟着切；`A().audio` 随项目存盘）。
- **文档**：`docs/firmware-contract.md` 新增第三节「速度档怎么跟着音乐走」并重编号（原三～六 → 四～七）；补丁清单新增 [7]（速度档，无需补丁），原 [7] 变 [8]；工具内帮助页加说明；README / CLAUDE.md（新增坑 15）同步。
- **测试**：+16 条，合计 **437**。真编译套件新增「前 18 拍慢档 + 后 19 拍快档」场景（C 侧与 JS 逐字节一致 + 快档段确实与原慢档不同）；`test_effects_core` 加信号链 7 条；`test_anim2` 加自动档接线 6 条；`test_help` 加帮助页 1 条。
